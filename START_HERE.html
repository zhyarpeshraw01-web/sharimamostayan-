A complete questionnaire website for Zhyar, Akam, Bria, Yasr, Nma, Layad, Snur and Soma.

Open the website ↗
Read this first: The ZIP opens in local mode. Uploading it alone does not activate shared answers. Follow the one-time Firebase setup below to connect all eight devices to the same database. No Firebase project has been created or connected for you.

01 Try the website first

Extract the ZIP, then open index.html. Choose a name at the top right. Open a chapter and try a question. Each member has a separate answer and optional rating.

In this mode the data stays in the current browser. Another computer will not see it. The local name selector is not a security feature.

Before switching to live mode: export any local answers you want to keep. Local answers are not automatically uploaded. Re-enter them after signing in to each member’s live account.

02 Create a Firebase project

  1. Open Firebase Console and sign in to your Google account.
  2. Create a project, for example Shari Mamostayan Study. Analytics is not needed for this website.
  3. Register a Web app using the web icon </>. You do not need Firebase Hosting if you plan to use GitHub Pages.
  4. In Project settings → General → Your apps, find the web configuration object called firebaseConfig. You will copy it in step 6.

Use a no-cost plan if available and suitable for your usage. Monitor the Firebase usage dashboard; service quotas and availability are controlled by Firebase. This app needs Authentication and Firestore only.

03 Create the database & publish rules

  1. Open Build → Firestore Database → Create database.
  2. Choose the Standard edition with native/Core operations, using the (default) database. Choose a suitable region before proceeding.
  3. Use production mode rather than open test rules.
  4. Open the Rules tab. Open firestore.rules from the extracted ZIP in a text editor, copy its entire contents, replace the editor contents in Firebase, then click Publish.
The supplied rules let assigned team members read all study answers. They can save only answers owned by their assigned name. Membership assignments cannot be changed from the website.

Keep the project key shari-mamostayan unchanged in config.js. It matches the supplied rules. Do not use a rule that allows everybody to read and write.

04 Create eight individual logins

  1. Open Build → Authentication → Get started.
  2. Under sign-in providers, enable Email/Password. The email-link option is not required.
  3. In Authentication → Users, use Add user to create a separate account for each member with their email and an individual password.
  4. Copy each account’s User UID. You will use the UID as a document ID in the next step.

Keep passwords private. Give each member only their own login details. Never paste passwords, service-account JSON or private keys into config.js or a public repository. The app has no open sign-up form.

For password changes or resets, manage the account through Firebase Authentication. Reset delivery is a separate owner action; this package does not send messages.

06 Connect your website configuration

Paste the web firebaseConfig object from Firebase below. The helper reads the standard public web fields and downloads a ready-to-use config.js. It does not send your configuration anywhere.

Replace the original config.js in the extracted website folder with this downloaded file. Keep the filename exactly config.js, even if your browser adds “(1)” to the download.

Prefer to edit the file manually?

Open config.js in a text editor and replace null with the configuration object:

window.URBAN_CONFIG = {
  projectKey: "shari-mamostayan",
  firebase: {
    apiKey: "YOUR_WEB_API_KEY",
    authDomain: "YOUR_PROJECT.firebaseapp.com",
    projectId: "YOUR_PROJECT",
    appId: "YOUR_APP_ID"
  }
};

The Firebase web configuration is meant to be used in a website. Its presence does not grant administrator access; Authentication and Firestore rules control data access.

07 Upload the website

The website has no build step. It can run on a static HTTPS host such as GitHub Pages.

  1. Create or open your website repository. Upload the contents of the extracted folder, not the ZIP itself. index.html must be at the publishing root.
  2. Keep assets/ and source/ as folders. Upload your updated config.js.
  3. For GitHub Pages, go to the repository’s Settings → Pages. Choose Deploy from a branch, select the branch containing your files and /(root), then save.
  4. Wait for GitHub’s deployment to finish and open the published HTTPS address.
  5. In Firebase Authentication → Settings → Authorized domains, add the host part of your website address, for example yourname.github.io. Do not include https:// or the repository path.
  6. Share the same website address with all eight members.

Live mode must be opened from the hosted address. A local file:// page is only for trying local mode.

Only website files belong in the public repository. Passwords, exported team answers and private evidence do not.

08 Check live collaboration

Complete this short check before the team starts real fieldwork. It also verifies the Firebase connection, which cannot be tested until you provide your own project.

Optional: edit the same member’s same question in two browsers. When the saved revision differs, the app asks you to choose the latest answer or your draft. It should not silently replace the other version.

Troubleshooting

It still says “Local mode”

Check that your downloaded config.js replaced the original at the website root and that firebase is an object, not null. Refresh the hosted page, using a hard refresh if necessary.

“Your account has no team profile”

Check Firestore members/{UID}. The document ID must match the signed-in Authentication UID exactly. The field must be memberId, type string, with the correct lowercase member ID.

Permission denied

Publish the supplied rules, check the UID mapping, and confirm the project key is shari-mamostayan. Use the default Firestore database. Do not make rules public to bypass the error.

Sign-in fails or never loads

Check your email/password provider, email, password, web config and authorized domain. Use HTTPS. Live mode needs access to Firebase services and its Google-hosted JavaScript SDK; a content blocker or restricted network may block them.

Draft on this device / Offline

Your latest edit has not reached the team. Keep the draft, restore the connection, then click Save answer. It retries when the browser comes back online. Do not clear browser data. Reloading offline may not load the online SDK, so reopen when connected. Export JSON if you need a separate copy.

Two versions need your decision

Your own answer changed elsewhere after you began this draft. The current saved text is shown. Choose “Use latest saved answer” to discard this local draft, or “Save my draft over latest” to replace the saved answer with your draft. Both choices ask for confirmation.

A percentage or distance will not save

Solid and void values must both be between 0 and 100 and total 100%. Distance must be a nonnegative number with a unit. If you cannot estimate it, choose “Not sure — needs checking”. A draft with invalid fields remains on the device but is not counted in saved progress.

What happens to local mode answers?

They remain in that browser’s local workspace. They are not shared and do not upload automatically. Export them before connecting Firebase, then re-enter the selected answers under each person’s assigned account. JSON is an archive; automatic restore/import is not provided.

Notes on the questionnaire

The app includes the 15 general questions and the two sets of 10 policies from your PDF. Each question links to its original page. Wording is retained with minor capitalization and typographic cleanup.

The 1–5 ratings, evidence field, response status and some structured choices were added to help the team work. N/A and unrated answers are excluded from averages. The overall mean uses equal weight per rated response. This is a team assessment, not an official smart growth score.

No site observations have been invented or prefilled. “Needs checking” is a legitimate response when evidence is missing.
